# Переход приложения на Python и Django

## Дополнение – 02.10.2026

Владелец согласовал MariaDB с переносом существующих данных. Новый контур
использует Django Ninja, модели и миграции Django, mysqlclient, Gunicorn и nginx.
MariaDB устанавливается из репозитория Ubuntu и работает на самом сервере.
API имеет отдельный SQL-аккаунт с ограниченными правами; миграции и управление
сотрудниками выполняет оператор. Новые пароли хешируются BCryptSHA256;
проверка прежних Argon2-хешей сохраняется.

Новая установка создаётся командой `sudo ./scripts/install.sh`; повторный запуск
сохраняет закрытую конфигурацию и доступ.

Перед обновлением сохраняются зашифрованный дамп, uploads, контрольные суммы
файлов и отпечатки всех таблиц. Прежний образ оператора закрепляется до
пересборки. Восстановление выполняется в отдельную пустую базу и отдельный
Compose-проект; исходный контур сохраняется.

Интерфейс пока использует Django/Jinja2 и JavaScript. Возврат к Vue/TypeScript
ожидает выбора владельца. Следующие разделы описывают решение от 1 октября
до согласования MariaDB и nginx.

## Решение

1 октября 2026 года владелец поручил перевести весь сайт на Python + Django.
Решение заменяет прежний выбор FastAPI. Сервер API, страницы, кабинет и панель
офиса работают на Django 6.1.2. TypeScript, React, FastAPI и Starlette исключены
из приложения и lock-файлов. PostgreSQL, Caddy, дизайн и функции сохраняются.

## Организация

- `backend/club_api/urls.py` – Django URLconf для HTTP-контрактов.
- Обработчики областей используют Django `HttpRequest` и HTTP-ответы.
  Проверка прав выполняется явно до выполнения операций; тела проверяются Pydantic.
- `frontend/club_web/urls.py` и `views.py` – страницы, фрагменты, файлы и прокси API.
- HTML формирует штатный движок Django Jinja2 с включённым экранированием.
  Он сохраняет текущие шаблоны, макросы и оформление офиса.
- Минимальный JavaScript нужен для форм, плеера, PWA и Telegram Mini App.
- Uvicorn запускает Django через ASGI. Жизненный цикл открывает соединения,
  запускает один планировщик и закрывает ресурсы при остановке.
- SQL и транзакции остаются в существующем слое `db`: схема и ограничения
  роли API сохраняются. Вторая схема пользователей Django не создаётся.
- Bootstrap, управление сотрудниками и импорты остаются Python-командами оператора.

## Совместимость данных и доступа

Таблицы, UUID, PHC-хеши, поколения сессий и том `directus_uploads` сохраняются.
Переименование и перенос данных не требуются. Обновление использует прежние
SQL-миграции; не запускайте стандартный `manage.py migrate` поверх рабочей схемы.
Готовность API проверяет PostgreSQL и обязательные таблицы.

Сессии используют прежний Bearer JWT; cookie не предоставляют доступ к API.
Проверка актуальной роли, status, версии сессии и отзыв токена остаётся серверной.
Восстановление через сайт доступно выпускникам; сотрудники управляются оператором.
SSO/MFA не обходятся. Редактор не получает текст обращений и права администратора.

Ограничения размера тела, частоты запросов и доверенного прокси сохранены.
Django принимает один файл без полей; медиа проверяются по содержимому,
а доступ к закрытому аудио и диапазонам байтов проверяет API.
Цены, скидки, резерв и платёжные события рассчитываются в прежних транзакциях.

## Установка и проверка

Ubuntu: `sudo ./scripts/install.sh`. Повторный запуск сохраняет конфигурацию,
пароль администратора, контент и данные. Сборки исключают собственные исходники,
тесты, инструменты разработки и демоданные из рабочих образов.

Дополнительно к проверкам из [testing.md](../development/testing.md):

```bash
uv run --directory backend python manage.py check
uv run --directory frontend python manage.py check
```

Контейнеры по-прежнему запускают `python -m club_api.main` и
`python -m club_web.main`. API остаётся одним процессом; порт не публикуется наружу.
Зеркало экспортируется из тех же Django/Jinja2-шаблонов с публичными фикстурами;
оно не выполняет оплату, вход и операции с персональными данными.

## Обновление и откат

Используйте [runbook](../operations/deploy-runbook.md): сохраните согласованную
копию БД/uploads и ID прежних образов, соберите и поднимите новый стек,
проверьте `/ready`, вход, контент, загрузку файла и сохранение заявки.
При откате возвращаются совместимые предыдущие API/bootstrap/web-образы.
Изменения схемы при этой миграции отсутствуют; БД и тома не удаляют.

Проверки и результаты записываются в [журнале](../operations/project-state.md).
Локальный и CI-стенд не подтверждают работу реального домена, почты, оплаты
и Telegram; эти интеграции проверяются при публичном запуске.
