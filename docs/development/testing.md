# Проверка проекта

Зависимости API, web и команд оператора закреплены в трёх `uv.lock`.
Для разработки нужны Python 3.14 и uv; для SQL и полного приложения – Docker.
Для mysqlclient установите `libmariadb-dev pkg-config` на Ubuntu или
`mariadb-connector-c pkgconf` на macOS. На macOS при первой сборке укажите
`PKG_CONFIG_PATH=/opt/homebrew/opt/mariadb-connector-c/lib/pkgconfig`.

## Быстрые проверки

Из корня репозитория:

```bash
uv sync --directory backend --frozen
uv sync --directory frontend --frozen
uv sync --directory scripts --frozen
uv run --directory frontend playwright install chromium
uv run --directory backend ruff check club_api tests/python ../scripts/club_ops
uv run --directory backend ruff format --check club_api tests/python ../scripts/club_ops
uv run --directory frontend ruff check club_web tests/python
uv run --directory frontend ruff format --check club_web tests/python
uv run --directory frontend python ../scripts/checks/check-comments.py
uv run --directory frontend python -m club_web.build --output /tmp/club-web
uv run --directory frontend python ../scripts/checks/check-web-build.py /tmp/club-web
uv run --directory backend pytest -q
uv run --directory frontend pytest -q
uv run --directory frontend python ../scripts/tests/test-comments.py
uv run --directory backend python ../scripts/tests/test-measure-load.py
python3 scripts/tests/test-mariadb-ops.py
```

Без тестовой БД SQL-сценарии пропускаются. Пропуск не означает успешной проверки
сохранения данных. Live-сценарии выполняются отдельной командой ниже.

## Что проверяют тесты

| Область | Проверка |
|---|---|
| API и данные | Права ролей и SQL-роль, PHC/JWT, регистрация, платежные повторы, сумма и резерв |
| Web и шаблоны | Публичные страницы, кабинет и офис, экранирование HTML, ссылки, ошибки API |
| Браузер | Все разделы на 1440 и 390 px, поиск, сравнение, корзина, ошибки оформления, сохранённое, PWA, Telegram и плеер |
| Дайджест | Разбор источника, даты, ссылки, объём, пагинация, обновление и сохранение архива при ошибке |
| Операции | Конфигурация, установщик, копия, восстановление, нагрузочные ограничения и TLS |
| Выпуск | Собственные скомпилированные модули, разрешённые шаблоны/статика, отсутствие исходников, тестов и демоданных |

Регрессии системной проверки охватывают сбой создания платежа и позднюю оплату,
окончательный статус выполненной заявки, целочисленное округление и суммы выше
32-битного диапазона. С обеими базами проверяются удаление старых контактов,
закрытие переписки на лимите сообщений, удаление писем подтверждения при
обезличивании и атомарное посещение события. Браузерные регрессии проверяют сохранность полей корзины,
выход при недоступном API, поддержку над нижним меню, возврат к подписке и
сохранение офлайн-копии при временной ошибке сервера.

Находки ревью проверяют
[test_review_security.py](../../backend/tests/python/test_review_security.py) и
[test_review_regressions.py](../../backend/tests/python/test_review_regressions.py).
Сценарии включают повторную отмену платежа, потерянный идентификатор и обход
нескольких пачек резервов, отзыв аудиоссылок после удаления профиля, неполный
каталог ДПО, конкурентную отправку письма, одинаковые slug в разных каталогах,
пустые фильтры, фотографии завершённых событий и досрочное продление подписки.
На 390 и 1440 px браузер проверяет повтор загрузки главной, передачу типа
позиции корзины, продление и сохранность галереи при редактировании товара.

Источники: [API](../../backend/tests/python), [web](../../frontend/tests/python),
[операции](../../scripts/tests). Подмена внешнего провайдера проверяет контракт,
но не подтверждает доставку реальной почты, оплату или работу Telegram.

## Настоящая MariaDB

Для отдельной локальной пустой базы `django_migration_test`:

```bash
CLUB_TEST_DATABASE_URL='<подключение к локальной тестовой MariaDB>' bash scripts/tests/test-mariadb-integration.sh
```

Подготовьте оператора с правами миграций, управления выделенным тестовым аккаунтом
и выдачи разрешений. Команда применяет миграции Django, ограничивает права
`club_api` и запускает весь серверный набор. Фикстуры очищают таблицы после
каждого сценария. Рабочая база для этой команды не подходит.

Дополнительно проверяются правила удаления внешних ключей, права API, команды
оператора и поиск на кириллице.

## Нативная установка и браузер с MariaDB

На отдельной Ubuntu 24.04 с Docker, uv и установленным Chromium:

```bash
CLUB_NATIVE_BROWSER=true bash scripts/tests/test-install.sh
```

Команда создаёт собственные базу, аккаунты, конфигурацию и Compose-проект.
Проверяет HTTPS с собственной доверенной CA, первичный вход и сценарии сайта
на 1440 и 390 px. Повторные bootstrap и миграции сохраняют пароли, роли и сессии;
поддержка включается только на этом стенде с вымышленными реквизитами.
После рестарта браузер проверяет записанные данные. Затем установщик запускается
повторно, выполняются зашифрованная копия и восстановление в отдельный контур.
Сверяются все таблицы, uploads и вход с прежним паролем. Затем тот же снимок
восстанавливается в сам установленный контур: проверяются отказ по чужому адресу
сайта, сохранение прежних базы и файлов и вход после выкладки. Тест удаляет только
созданные им базы, аккаунты, контейнеры и временные каталоги.

В браузере закрепляется ключ конкретного тестового TLS-сертификата, а запросы
Playwright доверяют его CA через `NODE_EXTRA_CA_CERTS`. Общая проверка TLS
не отключается. Установленные Python-пакеты и Chromium нужны в окружении теста;
в рабочие образы они не добавляются.

Без `CLUB_NATIVE_BROWSER=true` проверяются установка, повторный запуск и
восстановление; браузерный сценарий этого контура не выполняется. В CI он включён.
Не запускайте тест на портах, занятых рабочим сайтом: нужны 9080, 9443, 8025,
9543–9544 и 8125.

## Браузерный сценарий с настоящими сервисами

Сценарий `frontend/tests/python/test_live.py` запускается внутри
`CLUB_NATIVE_BROWSER=true bash scripts/tests/test-install.sh` на установленном
стенде MariaDB и nginx с Mailpit. Проверяются регистрация, письмо подтверждения,
вход, роли, профиль, медиа, корзина и заявка, подписка, события, отзыв сессии и
восстановление доступа. Через формы офиса создаются, изменяются и удаляются
программы, товары, новости, события и подкасты. Проверяются публикация новости
из источника, скрытие публикации, редактирование главной, CSV, скидка, баллы и
выдача подписки. В кабинете проверяются фото, интересы и отсутствие выгрузки
данных и привязки Telegram; в поддержке – обращение, ответ, продолжение
переписки, закрытие и удаление. После рестарта проверяются приглашение в друзья,
принятие и удаление связи. В каждом браузере открываются разделы сайта и офиса
с настоящим API и проверкой ширины страницы.

## Безопасность и содержимое образов

```bash
bash scripts/checks/check-runtime-images.sh API_IMAGE BOOTSTRAP_IMAGE WEB_IMAGE
```

Собственные Python-пакеты поставляются как `.pyc` и необходимые JSON; web
добавляет Jinja2-шаблоны и публичные CSS, JavaScript, изображения и шрифты.
API не содержит каталога bootstrap и демозаписей. Сторонние библиотеки и их лицензии
сохраняются. Node, npm, pnpm, uv, pip, pytest и линтеры в runtime отсутствуют.
UID приложения – 1000.

[CI](../../.github/workflows/ci.yml) проверяет зависимости каждого Python-пакета
через pip-audit, шесть образов через Trivy (High/Critical), Go-модули Caddy,
всю историю git через Gitleaks, а также установку и повторный запуск на Ubuntu.
Лицензионные уведомления и shebang допускаются проверкой комментариев.

## Как фиксировать результат

Указывайте SHA, команду, код завершения и окружение. Результат PR относится
к его проверенному коммиту; после слияния сверяется отдельный CI `main`.
Пароли, JWT, коды подтверждения, переписку и полный env в отчёт не копируют.
Команды выпуска и отката находятся в [runbook](../operations/deploy-runbook.md).
