# Конфигурация и секреты

Источники настроек: [.env.example](../../.env.example),
[config.py](../../backend/club_api/core/config.py), [Compose](../../docker-compose.yml),
[Dockerfile web](../../deploy/web.Dockerfile), [Caddy](../../deploy/edge.Dockerfile) и
операционные скрипты. Рабочее состояние конкретного контура – в
[project-state.md](../operations/project-state.md), процедуры – в [deploy-runbook.md](../operations/deploy-runbook.md).

## Где хранить и как применять

На Ubuntu рабочий файл – `/etc/club/runtime.env`, каталог принадлежит `root` с
правами `0700`, файл – `0600`. В репозиторий входят только безопасные шаблоны.
Доступ к Docker socket фактически даёт доступ к секретам контейнеров; членство
в группе `docker` не является непривилегированным способом обслуживания.

`ENV_FILE` передаётся операции явно абсолютным путём. Скрипты читают файл как
данные, а не исполняют его через `source`. Не помещайте в него команды shell,
многострочные значения или зависимости от подстановки команд. Значения с пробелами
заключайте в кавычки. Для случайных секретов удобно использовать hex без
символов, требующих дополнительного экранирования.

Compose подставляет переменные env только туда, где они перечислены в
`docker-compose.yml`. Само добавление новой строки в файл не передаёт её API.
Переменная окружения процесса, запускающего Compose, имеет приоритет над env-файлом;
оператор должен избегать случайного наследования настроек другого стенда.

В таблицах `〈секрет〉` означает инструкцию сгенерировать отдельное значение, а не
готовый пароль. Домены `example.org` и адреса `example.com` – примеры, не рабочие
назначения. Их не надо использовать для проверки доставки.

Этапы:

- **Запуск** – применяется при создании/пересоздании контейнера.
- **Инициализация** – используется при подготовке БД, bootstrap или миграциях.
- **Сборка** – попадает в статический bundle; после изменения требуется пересборка `web`.
- **Операция** – читается скриптом на Ubuntu; не передаётся браузеру.

тома `directus_uploads` сохранены для совместимости данных.

`manage-staff` не принимает пароль аргументом командной строки, не меняет роль
существующего пользователя и не снимает блокировку, MFA или внешний provider.
Команда требует владельца таблицы пользователей, а не runtime SQL-роли. Сброс
пароля повышает поколение admin-сессии и делает старые JWT недействительными.

Пароли уже созданных пользователей и БД не сбрасываются простым редактированием
переменной начальной инициализации. Ротация выполняется согласованно в данных,
секретах и зависимых сервисах; проверка входа после ротации обязательна.

`NODE_ENV=production` в образе управляет библиотеками Node, но не заменяет
`APP_ENV=production`. При ошибках production-конфигурации API не должен принимать
запросы. Публичный URL не должен содержать пароль, query, fragment или путь
приложения вместо корня. Адрес API `0.0.0.0` внутри контейнера допустим; публикация
его порта на хосте запрещена проектной конфигурацией.

Mailpit и проверяйте письмо в нём; не подставляйте реальные внешние учётные данные
ради теста. Факт принятия письма SMTP ещё не подтверждает доставку адресату.

## Обслуживание на Ubuntu

Настройки таймеров хранятся отдельно в `/etc/club/operations.env` (`root:root`,
`0600`). Systemd подхватывает этот файл; приложение его не читает.

Настройки этой таблицы не попадают в контейнеры приложения. `ENV_FILE`, пути,
restore-параметры и пороги скриптов передаются окружением запускающей команды или
systemd. `BACKUP_ENCRYPTION_KEY`, `BACKUP_OFFSITE_REMOTE` и `BACKUP_KEEP_DAYS`
скрипт читает из рабочего env с приоритетом окружения процесса.

| Переменная | Назначение | Обязательность | Секрет | Безопасный пример | Этап |
|---|---|---|---|---|---|
| `ENV_FILE` | Абсолютный путь к внешнему рабочему env | Да для операций | Путь, не содержимое | `/etc/club/runtime.env` | Операция |
| `DEPLOY_COMPOSE_OVERRIDE` | Дополнительный Compose-файл | Для QA/restore; необязательно для штатного сервера | Может содержать закрытые настройки | `/etc/club/qa-compose.yml` | Операция |
| `BACKUP_DIR` | Каталог снимков | По умолчанию `/var/backups/club` | Данные закрытые | `/var/backups/club` | Операция |
| `STATE_DIR` | Блокировка и результаты обслуживания | По умолчанию `/var/lib/club-ops` | Закрытые служебные данные | `/var/lib/club-ops` | Операция |
| `BACKUP_ENCRYPTION_KEY` | Шифрование снимка | Да, 64 hex-символа; хранить отдельно от копий | Да | `〈64 hex〉` | Операция |
| `BACKUP_OFFSITE_REMOTE` | Настроенное назначение rclone | Для внешнего хранения; пусто означает только локальную копию | Имя remote; его учётные данные отдельно | `backup:club` как условное имя | Операция |
| `BACKUP_KEEP_DAYS` | Хранение завершённых локальных снимков | По умолчанию `14`, положительное целое | Нет | `14` | Операция |
| `MIN_FREE_DISK_MB` | Минимальный свободный объём для preflight | По умолчанию `5120` MiB | Нет | `5120` | Операция |
| `HTTPS_CA_FILE` | Файл доверенного тестового CA для HTTPS | Только для локального CA | Публичный сертификат; не закрытый ключ | `/etc/club/qa-root.crt` | Операция |
| `RESTORE_PROJECT` | Новое имя изолированного Compose-проекта | Да при restore; префикс `club-restore-` | Нет | `club-restore-rehearsal` | Операция |
| `RESTORE_CODE_DIR` | Чистый checkout целевой версии восстановления | Обязателен для restore | Нет | `/opt/club-restore-code` | Операция |
| `RESTORE_MODE` | Точное восстановление или перенос legacy-копии | По умолчанию `exact`; альтернатива `migrate-legacy` | Нет | `exact` | Операция |
| `LEGACY_APP_REVISION` | Подтверждённый SHA источника legacy snapshot | 40 hex, обязателен для `migrate-legacy`, совпадает с commit.txt | Нет | SHA из проверенной версии источника | Операция |
| `ADOPT_DEPLOYED_REVISION` | Подтверждённый SHA старого образа без revision label | Только если метки образа нет; не версия нового checkout | Нет | SHA из прежнего выпуска | Операция |
| `SNAPSHOT_DIR` | Каталог выбранного завершённого снимка | Да при restore | Путь к закрытым данным | `/var/backups/club/snapshot-〈идентификатор〉` | Операция |
| `MONITOR_BACKUP_MAX_HOURS` | Максимальный возраст успешной копии | По умолчанию `36` | Нет | `36` | Операция |
| `MONITOR_CERT_MIN_DAYS` | Порог остатка срока сертификата | По умолчанию `14`; для короткого тестового сертификата Caddy локально `0.25` | Нет | `14` | Операция |
| `MONITOR_DISK_PERCENT` | Порог занятости диска | По умолчанию `85` | Нет | `85` | Операция |
| `MONITOR_MEMORY_PERCENT` | Порог использования памяти | По умолчанию `90` | Нет | `90` | Операция |
| `UPTIME_URL` | Адрес старого отдельного uptime-скрипта | Только при его отдельном использовании | Нет | `https://club.example.org/api/ready` | Операция |
| `UPTIME_STATE` | Состояние отдельного uptime-скрипта | Необязательно | Закрытые служебные данные | `/var/lib/club-ops/uptime.state` | Операция |

Сохранение настроек не устанавливает timer и не создаёт remote rclone. Дневной
backup и мониторинг устанавливаются по [runbook](../operations/deploy-runbook.md); старый cron
тех же операций не должен работать параллельно. Основной мониторинг пишет в
journald и возвращает код завершения; внешний канал не считается настроенным.
Отдельный uptime-скрипт может использовать `OFFICE_TG_*` только после явной настройки
оператором и проверки доставки.

## Сборка интерфейса и локальная разработка

Настройки прежней сборки `VITE_*` не используются. Web использует
[`API_INTERNAL_URL`](#настройки-web) для чтения API; статическое зеркало и
полный серверный стенд – разные контуры проверки. Флаги интеграционных тестов
`RUN_DATA_INTEGRATION`, `RUN_NATIVE_AUTH_INTEGRATION`,
`RUN_CHECKOUT_INTEGRATION`, `RUN_SUPPORT_INTEGRATION`, `RUN_TELEGRAM_INTEGRATION`
задаёт тестовый сценарий, они не являются настройками рабочего приложения.
`NATIVE_BOOTSTRAP_TEST_DATABASE_URL` допускает только выделенный локальный сервер
с БД `club_native_test`; тест создаёт временные базы и требует права CREATE DATABASE.
`VCS_REF` в сборке задаёт метку версии образа, не является секретом или runtime-настройкой.
Внутренние `MONITOR_URL`, `MONITOR_JOBS`, `MONITOR_DPO`, `MONITOR_NEWS` вычисляет
monitor.sh из рабочих настроек; отдельно задавать их оператору не требуется.

## Контроль после изменения

1. Установить, применяется настройка при сборке, запуске или операции.
2. Проверить конфигурацию без вывода секретов и пройти preflight нужного контура.
3. Пересобрать/пересоздать только требуемые компоненты по runbook.
4. Проверить `/api/ready`, пользовательский маршрут и затронутую интеграцию.
5. При ротации проверить, что новые ключи работают, а отозванные больше не принимаются.

Нельзя публиковать полный вывод `docker compose config`, `docker inspect`,
`printenv` или содержимое рабочего env: они могут содержать секреты.

## Проверка внешних интеграций перед выпуском

Владелец определяет включённые каналы и разрешённые тестовые операции. Для каждого
канала фиксируйте окружение, SHA, настройку, фактический результат и ограничение:

| Канал | Что проверить на целевом окружении |
|---|---|
| SMTP | Разрешённый отправитель, доставку подтверждения и восстановления в согласованный тестовый ящик, ссылки с рабочим доменом, обработку ошибки доставки |
| ЮKassa | Тестовый магазин, сумма и валюта, привязка оплаты к своей заявке, webhook, повторная доставка и отказ неверного источника; реальные платежи требуют отдельного поручения |
| Telegram | Бота и получателя офиса, webhook secret или выбранный polling, права чата, подписанный Mini App-вход; сообщения отправляются только по разрешению владельца |
| Web Push | Согласие пользователя, рабочую пару VAPID, получение на поддерживаемом устройстве и отказ подписки |
| Sentry | Разрешённого получателя ошибок и состав отправляемых сведений; отсутствие секретов и данных участника в проверочном событии |
| Offsite | Внешнее назначение и доступ, передачу зашифрованного снимка, проверку чтения и изолированное восстановление |
| Мониторинг | Выбранный внешний канал, тест сбоя и получения уведомления. Локальный journald не подтверждает внешнее оповещение |

Mailpit, локальная копия, флаг включения и наличие ключа не заменяют эту проверку.
Процедуры эксплуатации находятся в [runbook](../operations/deploy-runbook.md), выполненные
проверки и оставшиеся условия запуска – в [журнале состояния](../operations/project-state.md).


## Настройки web

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `API_INTERNAL_URL` | Внутренний адрес API; задаётся оператором, не браузером | `http://api:3000` в Compose, `http://127.0.0.1:3000` локально |
| `WEB_HOST` | Адрес прослушивания web | `127.0.0.1` локально, `0.0.0.0` в образе |
| `WEB_PORT` | Порт web | `5173` локально, `80` в образе |

Базовый путь зеркала передаётся аргументом `--base` экспортёру; это не настройка
рабочего сервера. Зеркало не читает рабочие секреты API.
