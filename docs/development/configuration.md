# Конфигурация и секреты

Источники настроек: [.env.example](../../.env.example) (начальные значения для мастера
установки), [config.py](../../backend/club_api/core/config.py) (настройки API),
[compose.mariadb.yml](../../deploy/compose.mariadb.yml),
[mariadb_install.py](../../scripts/lib/mariadb_install.py) (что мастер пишет в файлы),
[cli.py](../../scripts/club_ops/cli.py) (команды оператора) и
[Dockerfile web](../../deploy/web.Dockerfile). Рабочее состояние конкретного контура -
в [project-state.md](../operations/project-state.md), процедуры - в
[deploy-runbook.md](../operations/deploy-runbook.md).

## Файлы и как их применять

Мастер `sudo ./scripts/install.sh` пишет файлы в `/etc/club`: каталог принадлежит
`root` с правами `0700`, файлы - `0600`. В репозиторий входят только безопасные
шаблоны. Доступ к Docker socket фактически дает доступ к секретам контейнеров;
членство в группе `docker` не является непривилегированным способом обслуживания.

| Файл | Кто читает | Что внутри |
|---|---|---|
| `compose.env` | Compose и скрипты обслуживания через `ENV_FILE` | Переменные `CLUB_*`, `PUBLIC_URL`, порты, образы, `BACKUP_*`, `HTTPS_CA_FILE`, `COMPOSE_PROFILES` |
| `runtime.env` | Контейнер `api` (`CLUB_RUNTIME_ENV`) | Настройки API и `CHECKOUT_DATABASE_URL` аккаунта API |
| `operator.env` | Контейнер `operator` (`CLUB_OPERATOR_ENV`) | То же, что `runtime.env`, плюс `DATABASE_URL` оператора, `CHECKOUT_DB_*`, `ADMIN_EMAIL` и `ADMIN_PASSWORD` |
| `operations.env` | systemd (`EnvironmentFile`) | `ENV_FILE=/etc/club/compose.env` и `CLUB_STACK=mariadb` |
| `initial-admin.txt` | Оператор | Почта и пароль первого администратора |
| `install.json` | Мастер при повторном запуске | Режим установки, имена базы, аккаунтов и проекта |

Начальные значения мастер берет из `.env.example`. `CHECKOUT_DB_PASSWORD`,
`AUTH_SECRET`, `ADMIN_AUTH_SECRET`, `ADMIN_PASSWORD` и `BACKUP_ENCRYPTION_KEY` он
генерирует сам (64 hex-символа). В `runtime.env` не попадают `ADMIN_EMAIL`,
`ADMIN_PASSWORD`, `BACKUP_*`, `CHECKOUT_DB_*` и `TEST_*`. Повторный запуск мастера
сохраняет существующие файлы, пароли и данные.

`runtime.env` целиком передается контейнеру `api` через `env_file`, `operator.env` -
контейнеру `operator`; новая строка в этих файлах доходит до контейнера после его
пересоздания. Переменные `compose.env` подставляются только туда, где они упомянуты
в `compose.mariadb.yml`. Переменная окружения процесса, запускающего Compose, имеет
приоритет над `compose.env`; оператор должен избегать случайного наследования
настроек другого стенда.

Скрипты читают файлы как данные, а не исполняют их через `source`. Не помещайте в
них команды shell, многострочные значения или подстановку команд. Значения с
пробелами заключайте в кавычки. Для случайных секретов удобен hex без символов,
требующих экранирования.

В таблицах `〈секрет〉` означает инструкцию сгенерировать отдельное значение, а не
готовый пароль. Домены `example.org` и адреса `example.com` - примеры, не рабочие
назначения; их не надо использовать для проверки доставки.

Этапы:

- **Запуск** - применяется при создании или пересоздании контейнера.
- **Инициализация** - читается командами оператора: `migrate`, `configure-mariadb-role`, `bootstrap`.
- **Команда** - читается отдельной командой оператора.
- **Операция** - читается скриптом обслуживания на Ubuntu; не передается браузеру.

## База данных

| Переменная | Файл | Назначение | Секрет | Пример | Этап |
|---|---|---|---|---|---|
| `CHECKOUT_DATABASE_URL` | `runtime.env`, `operator.env` | Подключение к MariaDB: в `runtime.env` аккаунт API, в `operator.env` аккаунт оператора | Да | Пишет мастер | Запуск |
| `DATABASE_URL` | `operator.env` | Подключение команд оператора | Да | Пишет мастер | Инициализация / команда |
| `CHECKOUT_DB_USER` | `operator.env` | Имя аккаунта API, которому `configure-mariadb-role` задает права | Нет | `club_<суффикс>_api` | Инициализация |
| `CHECKOUT_DB_HOST` | `operator.env` | Хост аккаунта API в MariaDB | Нет | `localhost` | Инициализация |
| `CHECKOUT_DB_PASSWORD` | `operator.env` | Пароль аккаунта API | Да | `〈64 hex〉` | Инициализация |

Адрес имеет форму
`mariadb://<аккаунт>:<пароль>@localhost/<база>?unix_socket=/run/mysqld/mysqld.sock`;
специальные символы имени и пароля кодируются для URL. Принимаются только схемы
`mariadb://` и `mysql://` и только параметр `unix_socket` вместе с `localhost` и
абсолютным путем. Адрес PostgreSQL отклоняется. Без адреса API считает базу не
настроенной: запросы, которым нужна база, получают 503, фоновые задачи не
запускаются, а в production такой запуск запрещен проверкой конфигурации.

## Первый запуск и bootstrap

| Переменная | Назначение | Обязательность | Секрет | Пример | Этап |
|---|---|---|---|---|---|
| `ADMIN_EMAIL` | Начальный администратор приложения | Да | Закрытая служебная настройка | `admin@example.com` | Инициализация |
| `ADMIN_PASSWORD` | Пароль начального администратора | Да; генерирует мастер | Да | `〈отдельный случайный пароль〉` | Инициализация |
| `SEED_DEMO` | Синтетический контент и аккаунты | `false` в production | Нет | `false` | Инициализация / запуск API |
| `TEST_EDITOR_EMAIL`, `TEST_EDITOR_PASSWORD` | Демо-редактор | Только при `SEED_DEMO=true` вне production; мастер их не записывает | Тестовое значение | `editor@club.example.com` | Инициализация |
| `TEST_ALUMNI_EMAIL`, `TEST_ALUMNI_PASSWORD` | Демо-выпускник | Только при `SEED_DEMO=true` вне production; мастер их не записывает | Тестовое значение | `alumni@club.example.com` | Инициализация |

Пароли уже созданных пользователей и аккаунтов MariaDB не меняются простым
редактированием этих переменных. Ротация выполняется согласованно в данных,
секретах и зависимых сервисах; проверка входа после ротации обязательна.

## Команды оператора

Команды запускаются в образе оператора (`python -m club_ops.cli <команда>`) с
`operator.env`; порядок вызова - в [runbook](../operations/deploy-runbook.md#сотрудники-и-восстановление-доступа).

| Переменная | Назначение | Обязательность | Секрет | Пример | Команда |
|---|---|---|---|---|---|
| `STAFF_ACTION` | Создание или сброс пароля сотрудника | `create` или `reset-password` | Нет | `create` | `manage-staff` |
| `STAFF_EMAIL` | Адрес сотрудника | Да | Закрытая служебная настройка | `editor@example.com` | `manage-staff` |
| `STAFF_ROLE` | Ожидаемая роль сотрудника | `admin` или `editor` | Нет | `editor` | `manage-staff` |
| `STAFF_PASSWORD` | Новый пароль сотрудника | Альтернатива stdin, 12-100 символов | Да | Предпочтительно stdin из закрытого файла | `manage-staff` |
| `ALUMNI_EMAIL` | Почта выпускника, которого создает оператор | Да | Закрытая служебная настройка | `test.alumni@example.com` | `create-alumni` |
| `ALUMNI_FIO` | ФИО выпускника | Необязательно | Нет | `Тестовый Выпускник` | `create-alumni` |
| `ALUMNI_PASSWORD` | Пароль выпускника | Альтернатива stdin, 8-100 символов | Да | Предпочтительно stdin из закрытого файла | `create-alumni` |
| `TEST_MAIL_TO` | Адрес для проверочного письма | Да | Контакт | `operator@example.com` | `send-test-mail` |
| `CLUB_API_URL` | Корневой URL офисного API | По умолчанию `http://localhost`; снаружи только HTTPS | Нет | `https://club.example.org` | `import-podcasts` |
| `CLUB_ADMIN_TOKEN` | Действующая сессия офиса | Да для `import-podcasts` | Да | Передать через окружение | `import-podcasts` |

`manage-staff` не принимает пароль аргументом командной строки, не меняет роль
существующего пользователя и не снимает блокировку, MFA или внешний provider.
Команда работает от аккаунта оператора, а не аккаунта API. Сброс пароля повышает
поколение admin-сессии и делает старые JWT недействительными.
`setup-telegram-webhook` берет `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET` и
`PUBLIC_URL` из того же файла.

## API, сессии и адреса

| Переменная | Назначение | Обязательность | Секрет | Пример | Этап |
|---|---|---|---|---|---|
| `APP_ENV` | Проверка рабочей конфигурации | `production` на сервере; `development` для разработки | Нет | `production` | Запуск API |
| `API_HOST` | Адрес прослушивания API | В Compose `0.0.0.0` | Нет | `127.0.0.1` для локального процесса | Запуск |
| `API_PORT` | Внутренний порт API | В Compose зафиксирован `3000`; порт не публикуется | Нет | `3000` | Запуск |
| `UPLOADS_PATH` | Каталог файлов API | В Compose `/data/uploads`, на сервере это `CLUB_UPLOADS_DIR` | Нет | `/data/uploads` | Запуск API |
| `AUTH_SECRET` | Подпись сессий выпускников | Да, не короче 32 символов, без шаблонных значений | Да | `〈64 hex〉` | Запуск API |
| `ADMIN_AUTH_SECRET` | Отдельная подпись административных сессий | В production не короче 32 символов и отличен от `AUTH_SECRET` | Да | `〈другие 64 hex〉` | Запуск API |
| `PUBLIC_URL` | Адрес сайта, ссылки писем и оплаты | В production `https://<домен>` без пути | Нет | `https://club.example.org` | Запуск API и nginx |
| `CORS_ORIGINS` | Дополнительные разрешенные origin через запятую | Необязательно | Нет | Пусто для same-origin | Запуск API |
| `RATE_LIMIT_MAX` | Общий лимит запросов с IP за минуту | По умолчанию `1000` | Нет | `1000` | Запуск API |
| `SUPPORT_ENABLED` | Доступность поддержки | По умолчанию `false`; включать после определения оператора | Нет | `false` | Запуск API |
| `SUPPORT_OPERATOR_NAME` | Наименование оператора поддержки | При включении; значение по умолчанию задано в `config.py` | Нет | `〈подтвержденное наименование〉` | Запуск API |
| `SUPPORT_OPERATOR_ADDRESS` | Адрес оператора | При включении; значение по умолчанию задано в `config.py` | Нет | `〈подтвержденный адрес〉` | Запуск API |
| `SUPPORT_OPERATOR_CONTACT` | Контакт для обращений | При включении; значение по умолчанию задано в `config.py` | Нет | `〈подтвержденный контакт〉` | Запуск API |

При ошибках production-конфигурации API не запускается; выкладка проверяет это в
новом образе до остановки сайта. Публичный URL не должен содержать пароль, query,
fragment или путь вместо корня. Адрес API `0.0.0.0` внутри контейнера допустим;
публикация его порта на сервере запрещена конфигурацией.

## Почта и офисные уведомления

| Переменная | Назначение | Обязательность | Секрет | Пример | Этап |
|---|---|---|---|---|---|
| `OFFICE_NOTIFY_CHANNEL` | `email`, `telegram` или `both` | Да; выбранный канал должен быть настроен в production | Нет | `email` | Запуск API |
| `OFFICE_EMAIL` | Получатель писем офиса | Для `email` и `both` | Контакт | `office@example.com` | Запуск API |
| `OFFICE_TG_BOT_TOKEN` | Бот офисных уведомлений | Для `telegram` и `both` | Да | Пусто при отключении | Запуск API |
| `OFFICE_TG_CHAT_ID` | Чат офисных уведомлений | Для `telegram` и `both` | Закрытый идентификатор | Пусто при отключении | Запуск API |
| `SMTP_HOST` | Сервер почты | Обязателен в production; в репетиции `mailpit` | Нет | `smtp.example.org` | Запуск API |
| `SMTP_PORT` | Порт SMTP | По умолчанию `587` | Нет | `1025` для Mailpit | Запуск API |
| `SMTP_USER` | Учетная запись SMTP | По требованиям провайдера | Закрытая настройка | Пусто для Mailpit | Запуск API |
| `SMTP_PASS` | Пароль SMTP | По требованиям провайдера | Да | Пусто для Mailpit | Запуск API |
| `SMTP_FROM` | Разрешенный отправитель; без своего имени письма идут от «Клуб выпускников факультета права НИУ ВШЭ» | Нужен `SMTP_FROM` или `SMTP_USER` | Нет | `noreply@example.com` | Запуск API |
| `MAIL_REPLY_TO` | Адрес для ответов на письма сайта (Reply-To) | Нет; без него ответ уходит отправителю | Контакт | `club@example.com` | Запуск API |
| `MAIL_OUTBOX_MAX_ATTEMPTS` | Предел повторов доставки очереди | По умолчанию `8`, диапазон 1-50 | Нет | `8` | Запуск API |

Наличие `SMTP_HOST` включает подтверждение почты при регистрации. В development
без SMTP поведение регистрации отличается от production. При репетиции письма
остаются в Mailpit; не подставляйте реальные внешние учетные данные ради теста.
Принятие письма SMTP-сервером еще не подтверждает доставку адресату. Проверочное
письмо отправляет команда `send-test-mail`
([runbook](../operations/deploy-runbook.md#проверка-почты)); при ошибке она называет
ее тип, например отказ в авторизации, без пароля в выводе.

очищает реквизиты `PAYEE_*`, даже если исходная копия создана с включенными каналами. Персональные сообщения и рассылки не запускаются
операционными тестами без разрешения владельца.

| `ORDER_RETENTION_DAYS` | Срок обработки старых заявок политикой retention | По умолчанию `1095` | Нет | `1095` | Запуск API |
| `AUDIT_RETENTION_DAYS` | Срок хранения аудита | По умолчанию `365` | Нет | `365` | Запуск API |
| `SUPPORT_RETENTION_DAYS` | Срок хранения поддержки | По умолчанию `30`, диапазон 1-365 | Нет | `30` | Запуск API |
| `RESERVE_TTL_HOURS` | Срок резерва неоплаченных заявок | По умолчанию `72`, диапазон 0-720; 0 выключает истечение | Нет | `72` | Запуск API |

Эти сроки - действующие параметры проекта, а не универсальные законные сроки. Их
изменение затрагивает данные и согласуется с оператором. Расписания и различие
между планировщиком API и systemd описаны в [архитектуре](architecture.md#фоновые-задачи).

## Обслуживание на Ubuntu

Скрипты обслуживания читают `compose.env`, путь к нему передается в `ENV_FILE`.
Таймеры systemd получают `ENV_FILE` из `/etc/club/operations.env`. Приложение эти
переменные не читает.

| Переменная `compose.env` | Назначение |
|---|---|
| `CLUB_STACK` | `mariadb`; с другим значением скрипты не работают |
| `CLUB_PROJECT`, `CLUB_NETWORK` | Имя проекта и сети Compose, `club-mariadb-<суффикс>` |
| `CLUB_DATABASE` | Имя базы, `club_<суффикс>` |
| `CLUB_RUNTIME_ENV`, `CLUB_OPERATOR_ENV` | Абсолютные пути к файлам API и оператора |
| `CLUB_UPLOADS_DIR`, `CLUB_TRANSFER_DIR` | Каталоги файлов сайта и обмена, владелец UID 1000 |
| `CLUB_TLS_DIR` | Каталог `fullchain.pem` и `privkey.pem` |
| `CLUB_TLS_NAMES` | Дополнительные имена самоподписанного сертификата через запятую |
| `CLUB_STATE_DIR`, `CLUB_BACKUP_DIR` | Состояние операций и каталог копий |
| `CLUB_API_IMAGE`, `CLUB_WEB_IMAGE`, `CLUB_OPERATOR_IMAGE`, `CLUB_NGINX_IMAGE` | Образы одной ревизии |
| `PUBLIC_URL` | Адрес сайта для перенаправлений nginx |
| `CLUB_BIND_ADDRESS`, `CLUB_HTTP_PORT`, `CLUB_HTTPS_PORT` | Адрес и порты nginx |
| `COMPOSE_PROFILES` | `local` включает Mailpit; пусто для публичного домена |
| `CLUB_MAIL_PORT` | Порт Mailpit на loopback; по умолчанию `8025` |
| `CLUB_MARIADB_SOCKET_DIR` | Каталог сокета MariaDB; по умолчанию `/run/mysqld` |
| `BACKUP_ENCRYPTION_KEY` | Ключ шифрования копий, 64 hex-символа; хранить отдельно от копий |
| `BACKUP_KEEP_DAYS` | Хранение локальных копий, по умолчанию `14`, диапазон 1-3650 |
| `BACKUP_OFFSITE_REMOTE` | Назначение rclone; пусто - только локальные копии |
| `HTTPS_CA_FILE` | CA самоподписанного сертификата для проверок HTTPS в локальном контуре и контуре по IP |

| Переменная окружения команды | Назначение |
|---|---|
| `ENV_FILE` | Абсолютный путь к `compose.env`; обязателен для всех операций |
| `SNAPSHOT_FILE` | Зашифрованная копия для `restore.sh` |
| `RESTORE_ENV_FILE` | `compose.env` подготовленного контура восстановления |
| `RESTORE_SITE` | Адрес сайта контура, чьи база и файлы заменяются снимком; включает восстановление в рабочий контур |
| `SNAPSHOT_ENV_FILE` | `compose.env` сервера, где сделан снимок; нужен, когда ключ копий другой |

Команда `mariadb_native.py adopt-settings --source-env <runtime.env прежнего сервера>`
переносит настройки интеграций при [переезде](../operations/deploy-runbook.md#переезд-на-новый-сервер).
| `DEPLOY_COMMIT` | Коммит, который автовыкладка передает `deploy.sh` |
| `GITHUB_TOKEN` | Необязательный токен для чтения статуса CI автовыкладкой; без него запрос идет без авторизации |

Пороги обслуживания заданы в коде, а не переменными: выкладка требует 5 GiB
свободного места для сборки, монитор требует успешную копию не старше 36 часов и
предупреждает, когда сертификату осталось меньше 14 дней.

Сохранение настроек не устанавливает timer и не создает remote rclone. Дневная
копия и мониторинг устанавливаются по [runbook](../operations/deploy-runbook.md#таймеры-и-мониторинг).
Монитор пишет в journald и возвращает код завершения; внешний канал оповещения не
считается настроенным.

## Сборка и локальная разработка

`VCS_REF` в сборке задает метку версии образа; это не секрет и не настройка
запуска. Интеграционные тесты получают адрес одноразовой базы из
`CLUB_TEST_DATABASE_URL`; тесты принимают только локальную базу
`django_migration_test`. Это настройка тестов, а не рабочего приложения.

## Настройки web

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `API_INTERNAL_URL` | Внутренний адрес API; задается оператором, не браузером | `http://api:3000` в образе, `http://127.0.0.1:3000` локально |
| `WEB_HOST` | Адрес прослушивания web | `0.0.0.0` в образе, `127.0.0.1` локально |
| `WEB_PORT` | Порт web | `80` в образе, `5173` локально |

## Контроль после изменения

1. Установить, применяется настройка при сборке, запуске или операции.
2. Проверить конфигурацию без вывода секретов и пройти preflight нужного контура.
3. Пересобрать или пересоздать только требуемые компоненты по runbook.
4. Проверить `/api/ready`, пользовательский маршрут и затронутую интеграцию.
5. При ротации проверить, что новые ключи работают, а отозванные больше не принимаются.

Нельзя публиковать полный вывод `docker compose config`, `docker inspect`,
`printenv` или содержимое рабочих env-файлов: они содержат секреты.

## Проверка внешних интеграций перед выпуском

Владелец определяет включенные каналы и разрешенные тестовые операции. Для каждого
канала фиксируйте окружение, SHA, настройку, фактический результат и ограничение:

| Канал | Что проверить на целевом окружении |
|---|---|
| SMTP | Разрешенный отправитель, доставку кода подтверждения и восстановления в согласованный тестовый ящик, ссылки с рабочим доменом, обработку ошибки доставки |
| ЮKassa | Тестовый магазин, сумма и валюта, привязка оплаты к своей заявке, webhook, повторная доставка и отказ неверного источника; реальные платежи требуют отдельного поручения |
| Telegram | Бота и получателя офиса, webhook secret или выбранный polling, права чата, подписанный Mini App-вход; сообщения отправляются только по разрешению владельца |
| Web Push | Согласие пользователя, рабочую пару VAPID, получение на поддерживаемом устройстве и отказ подписки |
| Sentry | Разрешенного получателя ошибок и состав отправляемых сведений; отсутствие секретов и данных участника в проверочном событии |
| Offsite | Внешнее назначение и доступ, передачу зашифрованной копии, проверку чтения и изолированное восстановление |
| Мониторинг | Выбранный внешний канал, тест сбоя и получения уведомления. Локальный journald не подтверждает внешнее оповещение |

Mailpit, локальная копия, флаг включения и наличие ключа не заменяют эту проверку.
Процедуры эксплуатации находятся в [runbook](../operations/deploy-runbook.md),
выполненные проверки и оставшиеся условия запуска - в
[журнале состояния](../operations/project-state.md).
