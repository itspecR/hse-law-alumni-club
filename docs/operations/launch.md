# Запуск на домене

Порядок первого публичного запуска с чистой базой: домен, VPS, купленный
сертификат и почтовый хостинг Рег.ру с одним ящиком `club@<домен>`. Вместо `<домен>`
подставьте имя сайта без `www`, например `club-domain.ru`. Команды выполняются
на сервере из `/opt/club`.

## 1. Что подготовить

| Что | Требование |
|---|---|
| Домен | Доступ к записям DNS у регистратора |
| VPS | Ubuntu 24.04, вход root по SSH, входящие порты 80 и 443 открыты. В Рег.облаке сетевого фильтра в панели нет, порты закрывает ufw на самом сервере (шаг 3). Сервер оплачивается почасово с облачного счета: следите за балансом или включите автоперевод. Ресурсы – по [расчёту ёмкости](capacity.md); репетиция шла на 4 vCPU и 6 GiB RAM, диск нужен с запасом под ежедневные копии |
| Почта | Почтовый хостинг Рег.ру (тариф «Почта-1» или выше) с одним ящиком `club@<домен>` |
| Сертификат | Сертификат для `<домен>` и `www.<домен>` у регистратора, файлы в формате PEM |

## 2. DNS сайта

У регистратора:

| Тип | Имя | Значение |
|---|---|---|
| A | `@` (сам домен) | IP-адрес VPS |
| A | `www` | IP-адрес VPS |

Прежние записи A и AAAA для этих имён, например страницу-заглушку регистратора,
удалите. Изменения расходятся от нескольких минут до суток. Проверка на сервере:
`getent ahostsv4 <домен>` и `getent ahostsv4 www.<домен>` выводят IP-адрес VPS.

## 3. Сервер и код

Вход только по SSH-ключу. На компьютере, с которого входите (Windows PowerShell,
macOS или Linux), создайте ключ, если его нет, и передайте на сервер открытую часть.
Пароль root вводится один раз, при передаче ключа:

```bash
ssh-keygen -t ed25519 -C club-deploy
ssh root@<IP> "umask 077; mkdir -p .ssh; cat >> .ssh/authorized_keys" < ~/.ssh/id_ed25519.pub
ssh -o BatchMode=yes root@<IP> true
```

В Windows PowerShell вторая команда выглядит так:

```powershell
Get-Content $env:USERPROFILE\.ssh\id_ed25519.pub | ssh root@<IP> "umask 077; mkdir -p .ssh; cat >> .ssh/authorized_keys"
```

Последняя команда должна завершиться без запроса пароля. Закрытый ключ `id_ed25519` остается
на компьютере: не пересылайте его в почту и мессенджеры.

Когда вход по ключу работает, на сервере отключите вход по паролю и включите ufw.
Файлы в `/etc/ssh/sshd_config.d` читаются по алфавиту и действует первое значение,
поэтому `10-club.conf` перекрывает `50-cloud-init.conf`, если тот есть:

```bash
printf 'PasswordAuthentication no\nKbdInteractiveAuthentication no\n' > /etc/ssh/sshd_config.d/10-club.conf
sshd -t && systemctl reload ssh
sshd -T | grep -Ei '^(passwordauthentication|kbdinteractiveauthentication) '
ufw allow OpenSSH && ufw allow 80/tcp && ufw allow 443/tcp && ufw --force enable
ufw status verbose
```

`sshd -T` должен показать `no` в обеих строках. Не закрывайте текущую сессию SSH,
пока в новом окне не проверите вход по ключу. MariaDB слушает только локальный адрес,
а контейнеры обращаются к ней через сокет, поэтому ufw сайту не мешает.

Получите чистый Git checkout в `/opt/club` тем же способом, что и на тестовом
сервере: варианты – в README, раздел «Установка на Ubuntu». Репозиторий:
`https://github.com/itspecR/hse-law-alumni-club`.

## 4. Сертификат

1. Создайте ключ и запрос:
   ```bash
   cd /opt/club
   sudo ./scripts/certificate.sh request <домен>
   ```
   Команда выводит запрос (CSR) и папку `/etc/club-certificate/<время>`.
2. При заказе сертификата вставьте запрос у регистратора целиком. В запросе одно
   имя `www.<домен>` без дополнительных (SAN): Рег.ру не принимает запросы с SAN, а
   по имени с `www` удостоверяющий центр выпускает сертификат и на `www.<домен>`, и на
   `<домен>`. Оба имени в выданном сертификате проверяет шаг 4. Если регистратор сам
   создал запрос и ключ, не скачивайте и не используйте их: загрузите свой запрос.
   Владение доменом подтвердите записью DNS: сайта на этом шаге ещё нет.
3. Скопируйте файлы от регистратора на сервер, например командой `scp`.
4. Проверьте файлы и соберите цепочку:
   ```bash
   sudo ./scripts/certificate.sh prepare /etc/club-certificate/<время> <файл сертификата> <файл цепочки>
   ```
   Команда пишет «Сертификат проверен» и пути к `fullchain.pem` и `privkey.pem`.

Ключ `privkey.pem` остаётся на сервере: не отправляйте его регистратору, в почту
и мессенджеры.

## 5. Почта Рег.ру

1. В ispmanager почтового хостинга добавьте почтовый домен `<домен>` и создайте ящик
   `club@<домен>`. Пароль ящика нужен мастеру установки.
2. В DNS домена добавьте записи почты: MX на `mx1.hosting.reg.ru` и
   `mx2.hosting.reg.ru`, SPF (TXT для `@`) с `include:_spf.hosting.reg.ru`, DKIM (TXT),
   если его показывает ispmanager. Для DMARC добавьте TXT-запись `_dmarc` со значением
   `v=DMARC1; p=none`. Значения сверьте с панелью: в домене допускается одна запись SPF.

Сайт отправляет письма через `mail.hosting.reg.ru`, порт 465. На этом порту соединение
шифруется сразу (SSL), на других портах сайт требует STARTTLS. Сервер SMTP вашего
тарифа сверьте с разделом почты в панели Рег.ру.

## 6. Установка

```bash
cd /opt/club
sudo ./scripts/install.sh
```

Выберите контур `2 – публичный HTTPS` и ответьте:

| Вопрос мастера | Ответ |
|---|---|
| Домен сайта | `<домен>` |
| Email первого администратора | Почта человека, который входит в панель: на неё приходят коды входа |
| Сервер SMTP | `mail.hosting.reg.ru` |
| Порт SMTP | `465` |
| Логин SMTP | `club@<домен>` |
| Пароль SMTP | Пароль ящика из шага 5 |
| Разрешённый SMTP-отправитель | Enter |
| Email получателя заявок | Enter |
| Абсолютный путь к fullchain.pem | `/etc/club-certificate/<время>/fullchain.pem` |
| Абсолютный путь к privkey.pem | `/etc/club-certificate/<время>/privkey.pem` |

Мастер ставит Docker и MariaDB, собирает сайт и проверяет TLS, главную и
`/api/ready`. Первичные данные администратора: `sudo cat /etc/club/initial-admin.txt`.

## 7. Проверки

1. `https://<домен>` открывается без предупреждения браузера, а
   `https://www.<домен>` переходит на него.
2. Проверочное письмо на личную почту:
   ```bash
   sudo sh -c 'docker compose --env-file /etc/club/compose.env -f /opt/club/deploy/compose.mariadb.yml \
     run --rm --no-deps -T -e TEST_MAIL_TO=<личная почта> operator python -m club_ops.cli send-test-mail'
   ```
   Письмо пришло от «Клуб выпускников факультета права НИУ ВШЭ» и не попало в «Спам».
3. Вход в `/admin`: пароль из `initial-admin.txt`, затем код из письма. Смените
   пароль администратора.
4. Тестовая регистрация: код подтверждения приходит, анкета видна в панели на проверке.
5. Тестовая заявка на программу клуба: заявителю приходит «Заявка N принята»,
   на `club@<домен>` – «Новая заявка N».
6. Отмените тестовую заявку в панели и удалите тестовый профиль в кабинете.

## 8. Копии и мониторинг

Сделайте первую копию и проверьте сайт:

```bash
sudo env ENV_FILE=/etc/club/compose.env bash scripts/backup.sh
sudo env ENV_FILE=/etc/club/compose.env bash scripts/monitor.sh
```

После успешной копии включите таймеры по [runbook](deploy-runbook.md#таймеры-и-мониторинг).
Ключ копий из `/etc/club` сохраните отдельно в закрытом хранилище. Мониторинг пишет
только в журнал сервера и никого не оповещает.

Если на новый домен переносятся данные с прежнего сервера, после шага 7 выполните
[переезд](deploy-runbook.md#переезд-на-новый-сервер), а копии и таймеры включайте после него.

## 9. До объявления

- Тексты `/portfolio-consent` и `/portfolio-terms`: сейчас на страницах заглушки.
- Политика обработки персональных данных.
- Почта Оператора для правовых страниц (`operator.email` в `data/legal-data.json`)
  совпадает с ящиком `club@<домен>`; при смене ящика ее меняют отдельным изменением кода.

## 10. Продление сертификата

Купленный сертификат действует не дольше 200 дней, с 15 марта 2027 года – не дольше
100. Мониторинг предупреждает за 14 дней только в журнале сервера, поэтому поставьте
напоминание в календарь за 2–3 недели до окончания. Продление:

1. `sudo ./scripts/certificate.sh request <домен>` – новый ключ и запрос.
2. Перевыпуск сертификата у регистратора по новому запросу.
3. `sudo ./scripts/certificate.sh prepare <новая папка> <сертификат> <цепочка>`.
4. `sudo ./scripts/certificate.sh apply <новая папка>` – замена на работающем сайте.
   nginx перезапускается, сайт недоступен несколько секунд. При ошибке проверки
   возвращается прежний сертификат.
