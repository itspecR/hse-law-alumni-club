# Запуск на домене

Порядок первого публичного запуска с чистой базой: домен, VPS, купленный
сертификат и почта Яндекс 360 с одним ящиком `club@<домен>`. Вместо `<домен>`
подставьте имя сайта без `www`, например `club-domain.ru`. Команды выполняются
на сервере из `/opt/club`.

## 1. Что подготовить

| Что | Требование |
|---|---|
| Домен | Доступ к записям DNS у регистратора |
| VPS | Ubuntu 24.04, вход root по SSH, входящие порты 80 и 443 открыты, в том числе в сетевом фильтре панели хостинга. Ресурсы – по [расчёту ёмкости](capacity.md); репетиция шла на 4 vCPU и 6 GiB RAM, диск нужен с запасом под ежедневные копии |
| Почта | Яндекс 360 для бизнеса с платным тарифом и одним ящиком `club@<домен>` |
| Сертификат | Сертификат для `<домен>` и `www.<домен>` у регистратора, файлы в формате PEM |

## 2. DNS сайта

У регистратора:

| Тип | Имя | Значение |
|---|---|---|
| A | `@` (сам домен) | IP-адрес VPS |
| A | `www` | IP-адрес VPS |

Прежние записи A и AAAA для этих имён, например страницу-заглушку регистратора,
удалите. Изменения расходятся от нескольких минут до суток. Проверка на сервере:
`getent ahostsv4 <домен>` и `getent ahostsv4 www.<домен>` выводят IP-адрес VPS.

## 3. Код на сервере

Получите чистый Git checkout в `/opt/club` тем же способом, что и на тестовом
сервере: варианты – в README, раздел «Установка на Ubuntu». Репозиторий:
`https://github.com/itspecR/hse-law-alumni-club`.

## 4. Сертификат

1. Создайте ключ и запрос:
   ```bash
   cd /opt/club
   sudo ./scripts/certificate.sh request <домен>
   ```
   Команда выводит запрос (CSR) и папку `/etc/club-certificate/<время>`.
2. При заказе сертификата вставьте запрос у регистратора целиком. Владение доменом
   подтвердите записью DNS: почты на домене на этом шаге ещё нет.
3. Скопируйте файлы от регистратора на сервер, например командой `scp`.
4. Проверьте файлы и соберите цепочку:
   ```bash
   sudo ./scripts/certificate.sh prepare /etc/club-certificate/<время> <файл сертификата> <файл цепочки>
   ```
   Команда пишет «Сертификат проверен» и пути к `fullchain.pem` и `privkey.pem`.

Ключ `privkey.pem` остаётся на сервере: не отправляйте его регистратору, в почту
и мессенджеры.

## 5. Почта Яндекс 360

1. Подключите домен в Яндекс 360 и подтвердите владение записью, которую покажет
   Яндекс.
2. Добавьте у регистратора записи почты из Яндекс 360: MX, SPF (TXT) и DKIM (TXT).
   Для DMARC добавьте TXT-запись `_dmarc` со значением `v=DMARC1; p=none`.
3. Создайте ящик `club@<домен>`.
4. Создайте для этого ящика пароль приложения для почты и, если Яндекс этого
   требует, разрешите доступ почтовым программам. Точное место настроек в интерфейсе
   Яндекс 360 нужно уточнить при подключении.

Сайт отправляет письма через `smtp.yandex.ru`; подходят порты 587 и 465.

## 6. Установка

```bash
cd /opt/club
sudo ./scripts/install.sh
```

Выберите контур `2 – публичный HTTPS` и ответьте:

| Вопрос мастера | Ответ |
|---|---|
| Домен сайта | `<домен>` |
| Email первого администратора | Почта человека, который входит в панель: на неё приходят коды входа |
| Сервер SMTP | `smtp.yandex.ru` |
| Порт SMTP | Enter (587) |
| Логин SMTP | `club@<домен>` |
| Пароль SMTP | Пароль приложения из шага 5 |
| Разрешённый SMTP-отправитель | Enter |
| Email получателя заявок | Enter |
| Абсолютный путь к fullchain.pem | `/etc/club-certificate/<время>/fullchain.pem` |
| Абсолютный путь к privkey.pem | `/etc/club-certificate/<время>/privkey.pem` |

Мастер ставит Docker и MariaDB, собирает сайт и проверяет TLS, главную и
`/api/ready`. Первичные данные администратора: `sudo cat /etc/club/initial-admin.txt`.

## 7. Проверки

1. `https://<домен>` открывается без предупреждения браузера, а
   `https://www.<домен>` переходит на него.
2. Проверочное письмо на личную почту:
   ```bash
   sudo sh -c 'docker compose --env-file /etc/club/compose.env -f /opt/club/deploy/compose.mariadb.yml \
     run --rm --no-deps -T -e TEST_MAIL_TO=<личная почта> operator python -m club_ops.cli send-test-mail'
   ```
   Письмо пришло от «Клуб выпускников факультета права НИУ ВШЭ» и не попало в «Спам».
3. Вход в `/admin`: пароль из `initial-admin.txt`, затем код из письма. Смените
   пароль администратора.
4. Тестовая регистрация: код подтверждения приходит, анкета видна в панели на проверке.
5. Тестовая заявка на программу клуба: заявителю приходит «Заявка N принята»,
   на `club@<домен>` – «Новая заявка N».
6. Отмените тестовую заявку в панели и удалите тестовый профиль в кабинете.

## 8. Копии и мониторинг

Сделайте первую копию и проверьте сайт:

```bash
sudo env ENV_FILE=/etc/club/compose.env bash scripts/backup.sh
sudo env ENV_FILE=/etc/club/compose.env bash scripts/monitor.sh
```

После успешной копии включите таймеры по [runbook](deploy-runbook.md#таймеры-и-мониторинг).
Ключ копий из `/etc/club` сохраните отдельно в закрытом хранилище. Мониторинг пишет
только в журнал сервера и никого не оповещает.

## 9. До объявления

- Тексты `/portfolio-consent` и `/portfolio-terms`: сейчас на страницах заглушки.
- Политика обработки персональных данных.
- Почта Оператора `club@<домен>` для правовых страниц (`operator.email` в
  `data/legal-data.json`) вносится отдельным изменением кода.

## 10. Продление сертификата

Купленный сертификат действует не дольше 200 дней, с 15 марта 2027 года – не дольше
100. Мониторинг предупреждает за 14 дней только в журнале сервера, поэтому поставьте
напоминание в календарь за 2–3 недели до окончания. Продление:

1. `sudo ./scripts/certificate.sh request <домен>` – новый ключ и запрос.
2. Перевыпуск сертификата у регистратора по новому запросу.
3. `sudo ./scripts/certificate.sh prepare <новая папка> <сертификат> <цепочка>`.
4. `sudo ./scripts/certificate.sh apply <новая папка>` – замена на работающем сайте.
   nginx перезапускается, сайт недоступен несколько секунд. При ошибке проверки
   возвращается прежний сертификат.
